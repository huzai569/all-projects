CSS Combinators

A combinator sits between two selectors and says how the elements are related in the HTML tree. Every demo below runs a real selector on a real sample page and highlights what it matches.

␣descendant >child +adjacent sibling ~general sibling

How the browser reads a selector

HTML is a tree. Each element has a parent, may have children, and may have siblings that share its parent. Combinators use exactly these links.

Right to leftFor div p the browser finds every p first, then checks whether that p has a div above it.
Key selectorThe rightmost part is the element that gets styled. Everything to its left is only a condition.
No extra weightCombinators add no specificity. ul > li and ul li both weigh (0,0,2).

Common mistakes

  • Expecting + or ~ to select earlier siblings. They only look forward in the HTML order.
  • Using the descendant space when only direct children are wanted. Nested elements get styled by accident.
  • Expecting siblings to match across parents. h2 + p needs both elements under the same parent.
  • Long chains such as div ul li a span. They break when the HTML changes, so keep selectors short.
Spaces around >, + and ~ are optional, so div>p and div > p work the same.
